# Documentation map

**Summary:** Where each kind of knowledge lives. Read an index or a summary first; open a topic file only when the
task needs it. The rules for writing and growing these files are in `process/documentation.md`.

| File or folder | What it holds | Kind |
|---|---|---|
| [STATUS.md](STATUS.md) | Now, next, open questions. Read at the start of every session | Snapshot, rewritten |
| [HEALTH.md](HEALTH.md) | Ledger of periodic code-health checks; things noticed and not yet fixed | Ledger + list |
| [WORKING.md](WORKING.md) | Setup, commands, verification, performance budgets | Reference |
| [GLOSSARY.md](GLOSSARY.md) | One name per concept: the domain's terms and their names in code | Reference |
| [GOTCHAS.md](GOTCHAS.md) | Quirks found the hard way, one entry each | Reference, grows |
| [DESIGN.md](DESIGN.md) | Index of the design; the text is in `design/` | Index |
| [design/](design/) | One file per design topic | Topic files |
| [plans/](plans/) | Plans for larger work; finished ones in `plans/done/` | One file per plan |
| [ideas/](ideas/) | Ideas and the user's decisions on them, one file per topic | Topic files |
| [log/](log/) | What was done and decided, dated, one file per topic | Append-only |
| [process/](process/) | How work is done. Owned by the scaffold: extend it in `AGENTS.md`, not here | Reference |
